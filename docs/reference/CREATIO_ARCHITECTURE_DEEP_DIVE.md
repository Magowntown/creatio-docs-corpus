# Creatio Architecture Deep Dive

> **Source:** Analysis of D1_mkpdev-interweave (Creatio 8.1.3)
> **Purpose:** Understanding how Creatio operates for AI-assisted development
> **Updated:** 2026-02-05

---

## Executive Summary

Creatio is a **package-based, schema-driven** low-code platform built on:
- **.NET Framework** backend with WCF services
- **Angular-based Freedom UI** frontend
- **SQL Server/PostgreSQL** database with Redis caching
- **RabbitMQ** message broker for async operations

All customizations are contained in **packages**, which are deployment units containing **schemas** (code + metadata), **resources** (localization), and **data** (lookup values).

## 2. Package Architecture

### 2.1 What is a Package?

A **package** is the fundamental unit of customization in Creatio:
- Contains related functionality (entities, pages, processes)
- Has dependencies on other packages
- Can extend (inherit from) existing packages
- Is the unit of deployment between environments

### 2.2 Package Structure

```
Package_Name/
├── descriptor.json          # Package metadata & dependencies
├── Schemas/                 # Schema definitions
│   └── SchemaName/
│       ├── SchemaName.js    # JavaScript/C# code (SAFE TO EDIT)
│       ├── descriptor.json  # Schema inheritance info
│       ├── metadata.json    # Full schema definition
│       └── properties.json  # Schema type & version
├── Resources/               # Localization
│   └── SchemaName.Type/
│       └── resource.*.xml   # Language-specific strings
├── Data/                    # Lookup values & seed data
│   └── LookupName_Values/
│       ├── data.json        # Row data
│       ├── descriptor.json  # Data schema
│       ├── filter.json      # Import filter
│       └── Localization/    # Localized values
├── Assemblies/              # Pre-compiled DLLs (if any)
├── SqlScripts/              # Database migration scripts
├── Files/                   # Additional files (.csproj, etc.)
└── Autogenerated/           # ⚠️ NEVER MODIFY - System generated
```

| Type | ManagerName | Extension | Purpose |
|------|-------------|-----------|---------|
| **Entity** | EntitySchemaManager | `.Entity` | Database table definition |

| **Lookup** | — | `.Lookup` | Lookup configuration |
| **Data** | — | `.Data` | Package data |

### 3.1 Entity Schema (metadata.json)

Uses a proprietary diff format:
```
= MetaData.Schema.UId "e1169637-8d6e-48d6-a129-0362fbdb7f65"
= MetaData.Schema.A2 "IWPayments"                    # Name
= MetaData.Schema.D8 "1bab9dcf-..."                  # Parent UId (BaseEntity)
+ MetaData.Schema.D2 {                               # Add column
  "UId": "d0ab3549-...",
  "A2": "IWPaymentNumber",                           # Column name
  "S2": "ddb3a1ee-...",                              # Data type UId
  "E6": true,                                        # Is lookup?
  "S4": "25d7c1ab-...",                              # Referenced entity UId
  "E17": "IWAccountId",                              # Lookup Id column
  "E18": "IWAccountName"                             # Lookup display column
}
```

## 5. Runtime Architecture

### 5.1 Request Flow

```
Browser Request
      ↓
IIS / Web.config
      ↓
┌─────────────────────────────────────────┐
│           Terrasoft.WebApp              │
├─────────────────────────────────────────┤
│  ClientApp/         │  ServiceModel/    │
│  (Angular bundles)  │  (WCF .svc)       │
├─────────────────────────────────────────┤
│         Terrasoft.Configuration         │
│    (Compiled packages → bin/)           │
├─────────────────────────────────────────┤
│               conf/                     │
│  content/      runtime-data/    bin/    │
│  (JS files)    (db.sqlite)      (DLLs)  │
└─────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────┐
│              Infrastructure             │
├───────────┬───────────┬─────────────────┤
│   Redis   │  RabbitMQ │    SQL Server   │
│  (Cache)  │  (Queue)  │   (Database)    │
└───────────┴───────────┴─────────────────┘
```

### 5.2 Compilation Process

1. **Schema Changes** → `Pkg/{Package}/Schemas/`
2. **Compile All** → `Terrasoft.Configuration/bin/`
3. **Generate Content** → `conf/content/*.js`
4. **Update Metadata** → `conf/_MetaInfo.json`
5. **Runtime Cache** → `conf/runtime-data/db.sqlite`

### 5.3 Key Files

| File | Size | Purpose |
|------|------|---------|
| `conf/_MetaInfo.json` | 1.3MB | Schema version hashes |
| `conf/runtime-data/db.sqlite` | 91MB | Runtime configuration cache |
| `conf/content/*.js` | ~68MB | Compiled client modules |
| `bin/Terrasoft.Configuration.dll` | Variable | Compiled C# code |

## 9. Development Workflow

### 9.1 Clio CLI Commands

```bash
# Package operations
clio pull-pkg PackageName -e Environment    # Export
clio push-pkg PackageName -e Environment    # Import
clio delete-pkg PackageName -e Environment  # Delete

# Compilation
clio compile-all -e Environment             # Compile all
clio compile-workspace                      # Local compile
clio restart -e Environment                 # Restart app
clio clear-redis -e Environment             # Clear cache

# Health
clio ping Environment                       # Test connection
clio check-web-app-health -e Environment    # Health check
```

### 9.2 Safe Modification Points

| ✅ Safe | ⚠️ Careful | ❌ Never |
|---------|------------|----------|
| Custom package schemas | descriptor.json | Autogenerated/ |
| Resource XML files | SqlScripts/ | .Designer.cs |
| Package Data/ | System lookups data | Crt* packages |
| handlers[] | Business processes | Base* schemas |

### 9.3 Extension Pattern

Instead of modifying system schemas, **extend** them:

```json
// Schema descriptor.json
{
  "Descriptor": {
    "ExtendParent": true,
    "Parent": {
      "UId": "22cc919e-...",
      "Name": "Accounts_FormPage"
    }
  }
}
```

## 10. Key Insights for AI Development

### 10.1 Package Dependencies

Always check `descriptor.json` for dependencies before modifying packages. Missing dependencies cause import failures.

### 10.2 Schema Inheritance

Most customization uses the **ExtendParent** pattern:
1. Create new package
2. Add dependency on target package
3. Create schema with ExtendParent: true
4. Use viewConfigDiff to modify UI

### 10.3 Compilation is Required

Changes only take effect after compilation:
1. Schema changes → Compile All
2. Resource changes → May need restart
3. Data changes → Usually immediate

### 10.4 Cache Clearing

When changes don't appear:
1. Clear Redis cache
2. Clear browser cache
3. Restart application pool
4. Check _MetaInfo.json for hash updates

### 10.5 Date Format Consistency

Always use WCF date format for API calls:
```javascript
// Convert JavaScript Date to WCF
const wcfDate = `/Date(${date.getTime()})/`;
```

## 11. Common Gotchas

| Issue | Cause | Solution |
|-------|-------|----------|
| Changes not visible | Not compiled | Compile All |
| Package won't import | Missing dependency | Check descriptor.json |
| Grid not loading | Data source config | Check modelConfigDiff |
| Lookup not working | Wrong reference | Verify S4 in metadata |
| Localization missing | Resource file | Add resource.*.xml |
| Process not triggering | Signal config | Check trigger settings |
